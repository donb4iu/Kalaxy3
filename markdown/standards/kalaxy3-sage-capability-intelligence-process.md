# Kalaxy3 SAGE Capability Intelligence Process

## Purpose

SAGE renders what Kalaxy3 is trying to become, what is currently known, where
the target gaps are, which alternative changes are available, what each change
is predicted to require and achieve, what authority made the choice, and what
the actual outcome taught the engineering system.

The first implementation is a thin but complete walking skeleton. An immature
dimension remains visible and reduces confidence; it must not be converted into
false success, false failure, or an opaque aggregate score.

## Decision loop

1. Preserve operator intent and mission outcomes.
2. Discover scoped authoritative sources.
3. Render a versioned, evolvable preferred target.
4. Keep repository intent, live runtime, telemetry, economics, and historical
   evidence as separate assertions.
5. Surface conflicts, unknowns, freshness, confidence, and applicability.
6. Compare alternative branches, including a do-nothing baseline.
7. Preserve immutable discovery and pre-deployment predictions.
8. Record the designated decision authority and rationale.
9. Mutate only through repository-owned validation and approval.
10. Record actual values using the same subjects and units as predictions.
11. Feed prediction error, overrides, failures, and outcomes into SAGE learning.
12. Re-evaluate both the target and SAGE mission alignment.

## Federated authority

SAGE is a decision partner, not the sole authority. Operator intent, repository
desired state, Kubernetes runtime, Prometheus, Loki, Kubecost, hardware
inventory, external product contracts, AWS Well-Architected, AWS CAF, and SAGE
experience retain scoped authority.

Every assertion records its type, authority, timestamp, confidence, statement,
and evidence references. Conflicts remain visible until an authorized decision
resolves them. SAGE inference and prediction are never presented as source fact.

## Capability dimensions

Every capability renders functional outcome, runtime health, telemetry
visibility, evidence confidence, rebuild-forward readiness, security assurance,
operational maturity, and cost efficiency independently.

Unknown and not-applicable dimensions have no numeric score. SAGE does not
publish one overall capability percentage that could hide blockers or unknowns.

## WAR and CAF

All six AWS Well-Architected pillars and all six AWS Cloud Adoption Framework
perspectives are attached to each capability. They are assessment lenses, not
Kalaxy3 mutation authorities.

## Rebuild-forward assurance

A rebuild may intentionally create a better successor. The continuity contract
protects required outcomes, data, interfaces, recovery, and mission invariants.
It does not freeze current topology, products, tools, or historical sequencing.

Each affected capability is preserved, migrated, replaced, consolidated, or
explicitly retired.

## Predictions

Alternative branches include impact, scalar-neutral effort, cost, risk,
dependencies, reversibility, expected value, time to useful evidence, and
confidence. Predictions are versioned and digested before outcomes are known.

Actual values use the same subject and unit. Unavailable human engineering
effort remains null and inconclusive; automation elapsed time is never
misrepresented as human effort.

## Autonomy

SAGE currently may render facts, propose branches, and rank alternatives.
Mutation remains approval-gated. Greater autonomy must be delegated by domain
and earned through calibration, low failure rates, reversibility, and measured
successful outcomes.
